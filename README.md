# EVE Online Timerboard

Статус проекта: **версия 1.0 завершена и готова к эксплуатации**.

Онлайн-доска таймеров EVE Online с хранением данных в Supabase. Просмотр
защищается отдельным ключом, а добавление, редактирование и удаление доступны
только по админ-ключу через страницу `?admin=1`.

## Возможности

- добавление одного или нескольких таймеров из текста EVE;
- параметры по умолчанию для принудительного заполнения полей при массовом добавлении;
- проверка парсинга перед добавлением;
- ручное редактирование всех основных полей в админке;
- выбор типа структуры и типа таймера `Атака` / `Оборона`;
- отметки `Защищена`, `Уничтожена` и кнопка сброса результата;
- сортировка по любому столбцу нажатием на его заголовок, повторный клик меняет направление;
- поиск по системе, структуре, корпорации и альянсу;
- копирование названия системы одним нажатием на ячейку;
- показ завершённых таймеров за 12 часов, 24 часа, 3 дня, 7 дней или за всё время;
- физическая очистка завершённой истории из Supabase отдельной кнопкой главного администратора без удаления активных таймеров;
- фаза ремонта с длительностью, зависящей от типа объекта;
- 30 минут на ручную отметку результата для Metenox, POS, IHub и TCU;
- экспорт в CSV;
- отдельный сменяемый ключ для просмотра доски;
- отдельная вкладка с общей картой и маршрутами флотов;
- автоматическое распределение активных таймеров между флотами по графу EVE;
- мультифильтры общей карты и маршрутов флотов по атаке/обороне и типам объектов;
- профили флотов со стартовой системой, скоростью и временем на цели;
- отдельный хешированный ключ командира для каждого флота;
- право командира отмечать результат только у целей своего маршрута;
- журнал результатов, поставленных главным администратором или флотом.

## Роли и доступ

| Роль | Возможности |
|---|---|
| Зритель | Просмотр доски и общей карты после ввода ключа просмотра |
| Командир флота | Просмотр маршрута своего флота и установка результата у назначенных целей |
| Главный администратор | Добавление, редактирование и удаление таймеров, управление ключами и флотами, очистка истории |

Параметр `?admin=1` только открывает окно входа и сам по себе не предоставляет
прав. Каждая защищённая операция повторно проверяет ключ на стороне Supabase
через RPC.

## Поддерживаемые форматы

```text
III Hokage > Customs Office* (Yehaba II*) [The Weak And The Scrawny]<br>1,7 а.е.<br>Укрепленный режим до 2026.05.23 10:37:54
```

```text
[12:44:39] Tygarin Kvazovsky > Hakatiz - 7-6<br>8,4 AU<br>Reinforced until 2026.05.22 13:08:10
```

```text
Hakatiz - 7-6
9 149 м
В оборонном режиме до 2026.05.22 13:08:10
```

Поддерживаются также строки без переносов, например:

```text
Luciela Spartacus > Customs Office* (Balas I*) [The Weak And The Scrawny]560 560 кмУкрепленный режим до 2026.05.23 10:56:56
```

Время таймеров считается как EVE/UTC.

После указанного времени таймер не исчезает сразу. Для `Astrahus`, `Fortizar`,
`Keepstar`, `Raitaru`, `Azbel`, `Sotiyo`, `Athanor` и `Tatara` включается
15-минутная фаза `Ремонт`. Для `Customs Office` используется двухчасовой отсчёт.

Для `Metenox Moon Drill`, `POS`, `IHub` и `TCU` после основного времени
запускается 30-минутный обратный отсчёт. В течение него администратор может
выбрать итог `Защищена` или `Уничтожена`. Если итог не выбран, по истечении
30 минут запись автоматически переходит в завершённые таймеры.

## 1. Скачать проект

```powershell
git clone https://github.com/Nightcor157/eve-timerboard.git
cd eve-timerboard
```

## 2. Создать базу Supabase

1. Создай новый проект на Supabase. Название проекта и пароль базы придумай
   сам. Пароль базы нужен только для управления проектом, в код сайта его
   вставлять не нужно.
2. Открой `SQL Editor` и создай новый запрос.
3. Открой файл `supabase/schema.sql` из проекта.
4. Вставь его содержимое в SQL Editor и нажми `Run`.
5. После сообщения `Success` выполни отдельный запрос:

```sql
select public.setup_timerboard(
  'main',
  'ВВЕДИ_ЗДЕСЬ_СВОЙ_СЕКРЕТНЫЙ_АДМИН_КЛЮЧ'
);
```

Замени текст `ВВЕДИ_ЗДЕСЬ_СВОЙ_СЕКРЕТНЫЙ_АДМИН_КЛЮЧ` внутри кавычек на свой
ключ длиной не меньше 12 символов. Значение `main` оставь без изменений, если
используешь одну доску. Не записывай админ-ключ в файлы сайта и не отправляй
его другим пользователям.

Предупреждение Supabase о destructive operations ожидаемо: схема удаляет
только старые версии RPC-функции и старую политику открытого чтения. Таблицы и
таймеры не удаляются.

## 3. Настроить подключение сайта

В панели проекта Supabase нажми `Connect`. Скопируй `Project URL`. Затем открой
`Settings` → `API Keys` и скопируй ключ из раздела `Publishable key`. Обычно он
начинается с `sb_publishable_`. Если проект старый и такого ключа нет, можно
использовать `anon` из раздела `Legacy API Keys`.

Открой файл `js/config.js` и замени только два отмеченных значения:

```js
window.EVE_TIMERBOARD_CONFIG = {
  // Вставь сюда свой Project URL из Supabase:
  supabaseUrl: "https://ВВЕДИ_ЗДЕСЬ_ID_СВОЕГО_ПРОЕКТА.supabase.co",

  // Вставь сюда свой Publishable key (не Secret и не service_role):
  supabaseKey: "ВВЕДИ_ЗДЕСЬ_СВОЙ_sb_publishable_КЛЮЧ",

  boardId: "main",
  pollEveryMs: 15000
};
```

Друг должен обязательно заменить URL и ключ из исходного `js/config.js` своими
значениями от своего проекта Supabase. `boardId: "main"` менять не нужно, если
в команде `setup_timerboard` использовалось значение `main`.

Никогда не вставляй в `js/config.js` значения `Secret key`, `sb_secret_...` или
`service_role`: они дают повышенный доступ к базе. Для сайта нужен только
`Publishable key` или старый `anon` key. Админ-ключ и ключ просмотра в этот
файл тоже не добавляются.

Админ-ключ и ключ флота при включённой галочке запоминаются только до закрытия
вкладки (`sessionStorage`). Ключ просмотра может сохраняться между запусками
браузера (`localStorage`), потому что он даёт только чтение доски и маршрутов.

### Какие данные куда вводить

| Данные | Откуда взять | Куда ввести |
|---|---|---|
| Project URL | Supabase → `Connect` | `js/config.js`, поле `supabaseUrl` |
| Publishable key | Supabase → `Settings` → `API Keys` | `js/config.js`, поле `supabaseKey` |
| Админ-ключ | Придумать самому | SQL-команда `setup_timerboard`, затем поле `Админ-ключ` в админке |
| Ключ просмотра | Придумать самому | Поле `Новый ключ просмотра` в админке |
| `boardId` | Обычно оставить `main` | Одинаковое значение в SQL и `js/config.js` |

Пароль базы, `Secret key` и `service_role` сайту не требуются.

## 4. Задать ключ просмотра

1. Открой опубликованный сайт и нажми `Вид: пользователь` в верхнем меню.
2. Во всплывающем окне введи тот же админ-ключ, который указал в SQL-команде
   `setup_timerboard`. После проверки кнопка изменится на `Вид: админ`.
3. В админской панели в поле `Новый ключ просмотра` придумай отдельный ключ
   длиной не меньше 12 символов.
4. Нажми кнопку сохранения ключа.

После этого обычная страница доски откроется только после ввода ключа
просмотра. Изменить его позднее можно там же; старый ключ сразу перестанет
работать. Админ-ключ также подходит для чтения доски.

### Ротация и восстановление ключей

- Ключ просмотра меняется в админской панели; старый перестаёт работать сразу.
- Чтобы сменить или восстановить забытый админ-ключ, владелец проекта открывает
  Supabase SQL Editor и выполняет:

```sql
select public.setup_timerboard(
  'main',
  'НОВЫЙ_АДМИН_КЛЮЧ_НЕ_КОРОЧЕ_12_СИМВОЛОВ'
);
```

- Эта команда меняет только хеш админ-ключа. Таймеры, ключ просмотра, флоты и
  маршруты не удаляются.
- Старый админ-ключ после команды перестаёт работать. Исходный текст ключа из
  bcrypt-хеша восстановить нельзя, его можно только заменить.
- Ключ отдельного флота меняется кнопкой ротации в управлении флотами; старый
  ключ этого флота сразу становится недействительным.

## 5. Проверить базу

В SQL Editor можно проверить создание доски и таблиц:

```sql
select board_id, view_key_hash is not null as view_key_is_set
from public.timerboard_settings;

select count(*) as timers_count
from public.timers
where board_id = 'main';
```

Для полной проверки открой админку, добавь тестовый таймер, измени любое поле,
поставь результат и затем удали тестовую запись.

## Карта и маршруты флотов

Во вкладке `Маршруты` доступны два режима:

- `Общая карта` — пользователь выбирает стартовую систему, скорость
  перелёта и время на цели. Сайт по официальному графу EVE строит единый
  последовательный путь `старт → цель 1 → цель 2…`. При одном флоте и
  одинаковых параметрах расчёт совпадает с маршрутом флота;
- `Маршруты флотов` — главный администратор создаёт профили и запускает общий
  расчёт, а командир открывает сохранённый маршрут по ключу своего флота.

Вкладка `Маршруты` заблокирована, пока Supabase не проверит ключ просмотра.
Для маршрута флота нужны оба ключа: ключ просмотра доски и ключ выбранного
флота. Это проверяется не только интерфейсом, но и RPC-функциями базы.

Профиль флота задаёт текущую систему, среднее число секунд на один прыжок и
время работы на цели. Полный ключ флота показывается только один раз после
создания или смены. В базе хранится его хеш и последние четыре символа.
Кнопка `Сохранить профиль` меняет только параметры своего флота и не выпускает
новый ключ. Для этого есть отдельная кнопка `Новый ключ`.
Названия систем проверяются по локальному каталогу официального EVE SDE.
Перед расчётом общей карты и маршрутов флотов можно включить несколько сторон
таймера и типов объектов. Внутри группы действует `ИЛИ`, а между группами — `И`:
например, `Атака + Оборона` и `Athanor + Metenox Moon Drill` возьмут обе стороны,
но только эти два типа объектов.
Распределение сначала строит быстрый базовый план по ближайшим срокам, а затем
проверяет переносы и обмены целей между флотами. Улучшения сравниваются строго по
числу опозданий, суммарному опозданию, числу простаивающих флотов, разбросу
рабочего времени, разнице числа целей и затем по числу прыжков. Худший вариант
никогда не заменяет базовый. Если целей не меньше, чем активных флотов, каждый
флот получает работу, пока это не создаёт дополнительное опоздание. Более
быстрый флот может получить больше целей, если так общая нагрузка ближе к равной.
После расчёта администратор видит число опозданий, суммарные прыжки, разброс
нагрузки, время расчёта и отметку, удалось ли улучшить базовый план.
Последний рассчитанный общий маршрут не пропадает при переключении между режимами
`Общая карта` и `Маршруты флотов`.
В таблицах доски, общего маршрута и маршрутов флотов любой заголовок со стрелкой
сортирует строки по своей колонке. Повторное нажатие переключает порядок между
возрастанием и убыванием; сортировка таблицы не меняет рассчитанный путь на карте.
Карта показывает системы и ворота задействованных регионов по координатам EVE SDE,
а слабые подписи с названиями регионов помогают видеть границы перелёта.
Рассчитанные пути выделяются цветом. Цветная легенда позволяет временно скрывать
отдельные флоты только с карты, не убирая их цели из таблицы. Масштаб меняется
колесом мыши или кнопками
`−`/`+`, увеличенная карта перемещается зажатой ЛКМ. Подписываются только системы
маршрута, а размер текста адаптируется к масштабу. Высота меняется ручкой под
картой. Положение и высота запоминаются в браузере.

Для создания флотов:

1. Нажми `Вид: пользователь` и введи главный админ-ключ.
2. Перейди во вкладку `Маршруты` и выбери режим `Маршруты флотов`.
3. Создай профили и скопируй выданные ключи.
4. Нажми `Сохранить и рассчитать`. Изменённые профили сохранятся
   автоматически перед построением маршрутов.

Командир открывает обычный сайт, вводит ключ просмотра доски, выбирает свой
флот и вводит ключ флота. Кнопки `Защищена`, `Уничтожена` и `Сброс`
появляются прямо в строках его маршрута и в столбце `Итог` обычной доски.
Они доступны только у целей, назначенных этому флоту. У зрителя без ключа флота
этих кнопок нет. После установки итога доска автоматически включает показ
завершённых, немедленно обновляет строку и затем сверяет результат с Supabase.

Кнопка `Очистить закрытые таймеры из БД` находится в панели добавления таймеров
и появляется только после входа главным администратором. После подтверждения она
вызывает защищённую RPC и удаляет закрытые строки из `public.timers`; активные
таймеры и текущие окна ремонта остаются в базе.

Карта использует официальные координаты `position2D` и связи ворот из EVE
SDE: соседние системы показаны фоном, рассчитанный путь выделен цветом, а
старт и таймеры имеют отдельные маркеры. Карту можно увеличивать кнопками над
ней. Кнопка `Вид: админ` возвращает пользовательский интерфейс без
перезагрузки страницы.

## Проверка и сопровождение

Для проверок нужен Node.js 20 или новее. После клонирования установи зависимости
и браузер Playwright:

```powershell
npm ci
npx playwright install chromium
```

Основные команды:

```powershell
npm run test:syntax      # синтаксис всех JS/MJS-файлов
npm run test:unit        # парсер, жизненный цикл, маршруты и сервисы
npm run test:contracts   # обязательные SQL-контракты
npm run test:security    # CSP, версия SDK и безопасность общей SQL-схемы
npm run test:database    # полная схема в PostgreSQL WASM
npm run test:e2e         # короткие браузерные сценарии
npm run test:e2e:stress  # 40 таймеров, 4 флота и фильтры
npm test                 # полный обязательный набор
```

Тесты запускают временный локальный сервер, мокируют Supabase и ESI и не требуют
рабочих ключей. PGlite повторно выполняет полную схему в настоящем
PostgreSQL WASM, включая повторное обновление поверх сохранённых данных. При ошибке снимок
страницы сохраняется в `tests/artifacts/`.
Те же команды автоматически выполняет GitHub Actions для push и pull request в
ветку `main`.

Каталог `data/solar-systems.json` собран из официального
[EVE SDE](https://developers.eveonline.com/docs/services/static-data/) build
`3646012`. Для его
обновления после нового релиза SDE запусти:

```powershell
node scripts/build-system-catalog.mjs <mapSolarSystems.jsonl> <mapStargates.jsonl> data/solar-systems.json <номер-сборки>
```

Названия регионов для фоновых подписей карты лежат в `data/regions.json` и
получены из официального EVE ESI. Этот небольшой справочник не участвует в
расчёте маршрута: он нужен только для понятных подписей на карте.

## Поля базы данных

| Поле интерфейса | Колонка `public.timers` |
|---|---|
| ID таймера | `id` |
| Доска | `board_id` |
| Исходный текст | `raw_text` |
| Корпорация | `title` |
| Система | `system` |
| Объект | `object_name` |
| Структура | `structure` |
| Альянс | `owner` |
| Атака / Оборона | `distance` |
| Режим | `mode` |
| Укреплён до | `end_at` |
| Защищена / Уничтожена | `note` |
| Фактически завершён | `completed_at` |
| Создан | `created_at` |
| Изменён | `updated_at` |

Маршруты используют дополнительные таблицы `fleet_profiles`,
`fleet_assignments` и `timer_result_events`. Прямое чтение этих таблиц закрыто
RLS; браузер работает только через RPC с главным ключом или ключом флота.

Названия `title`, `owner` и `distance` сохранены для совместимости со старыми
данными. Интерфейс показывает их как `Корпорация`, `Альянс` и `Таймер`.

## Обновление существующей базы

В проекте поддерживается только один SQL-файл: `supabase/schema.sql`.
Используй его и для новой базы, и для обновления существующей. В Supabase открой
`SQL Editor`, вставь всё содержимое файла и нажми `Run`.

Скрипт можно выполнять повторно: он сохраняет таймеры, настройки доски, флоты,
назначения и хеши ключей, добавляет недостающие объекты и обновляет RPC. Сам
запуск SQL историю не удаляет: удаление происходит только после нажатия
`Очистить закрытые таймеры из БД` и подтверждения в админском виде.

Для текущего обновления используй такой порядок:

1. Сначала опубликуй новые файлы сайта.
2. Сразу после публикации выполни актуальный `supabase/schema.sql`.
3. Убедись, что запрос завершился сообщением `Success`, и обнови страницу.

Клиент на время обновления распознаёт только ошибку отсутствующей новой
сигнатуры `set_fleet_timer_result` и повторяет этот вызов по старому контракту.
Ошибки ключа, прав и конкурентного изменения не маскируются. После выполнения
схемы сервер отдаёт `timer_updated_at`, используется только новая защищённая
сигнатура, а старая функция удаляется схемой.

После обновления повторно выполнять `setup_timerboard` не нужно, если не
требуется поменять админ-ключ. Существующие ключи короче 12 символов продолжат
работать; ограничение в 12 символов применяется только при новой установке или
следующей ротации.

## Публикация на GitHub Pages

1. Загрузи изменения в свой GitHub-репозиторий.
2. Открой `Settings` → `Pages`.
3. Выбери `Deploy from a branch`, ветку `main` и папку `/root`.
4. Сохрани настройки и дождись публикации.

Обычная страница:

```text
https://ТВОЙ_НИК.github.io/eve-timerboard/
```

Админка:

```text
https://ТВОЙ_НИК.github.io/eve-timerboard/?admin=1
```

После следующих отправок изменений в ветку `main` GitHub Pages обычно
пересобирает сайт автоматически.

## Несколько досок

Для каждой доски создай отдельный `board_id` и админ-ключ:

```sql
select public.setup_timerboard('corp', 'КЛЮЧ_ДЛЯ_CORP');
```

Затем укажи тот же идентификатор в `js/config.js`:

```js
boardId: "corp"
```

## Ограничения версии 1.0

- граф маршрутов соответствует сохранённой сборке EVE SDE и требует обновления
  после изменений карты CCP;
- Ansiblex, червоточины и временные связи не учитываются;
- планировщик улучшает базовое распределение, но не гарантирует глобальный
  математический оптимум;
- общие ключи рассчитаны на закрытую доверенную группу, а не на публичный
  сервис с персональными аккаунтами;
- обновление схемы Supabase выполняется владельцем проекта вручную.

Все запланированные этапы разработки завершены. Исторические ТЗ, roadmap и
промежуточная память разработки удалены из рабочей версии репозитория; этот
README является единственным актуальным документом по установке, использованию
и сопровождению проекта.

## Локальный режим

Если URL или ключ Supabase не настроены, сайт работает в локальном режиме.
Таймеры тогда сохраняются только в текущем браузере и не видны другим людям.
