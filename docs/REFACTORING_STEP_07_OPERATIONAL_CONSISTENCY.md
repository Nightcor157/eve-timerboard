# ТЗ этапа 7: согласованность доски и истории

Статус: **выполнен**.

## 1. Цель

Устранить расхождение между маршрутом флота и общей доской после установки
итога, а также сделать физическую очистку закрытых таймеров из Supabase
доступной и понятной главному администратору.

## 2. Синхронизация итога

- после успешного `set_fleet_timer_result` маршрут передаёт доске идентификатор
  таймера и сохранённый итог;
- доска немедленно обновляет строку без ожидания 15-секундного опроса;
- при непустом итоге автоматически включается показ завершённых таймеров, чтобы
  обновлённая строка не исчезала из интерфейса;
- после локального обновления доска повторно вызывает `get_timers` и сверяет
  состояние с Supabase;
- при входе главного администратора завершённая история показывается
  автоматически, а при возврате в пользовательский вид восстанавливается
  прежнее состояние фильтра;
- другие открытые браузеры получают изменение при очередном штатном опросе.

## 3. Очистка истории в БД

- кнопка `Очистить закрытые таймеры из БД` находится внутри админ-панели;
- до серверной проверки главного админ-ключа кнопка скрыта;
- перед удалением показывается число закрытых записей и требуется подтверждение;
- клиент вызывает только защищённую RPC `clear_timer_history`;
- RPC повторно проверяет главный админ-ключ через
  `assert_timerboard_admin` и физически удаляет строки из `public.timers`;
- ключ просмотра и ключ командира флота не дают права очистки;
- таймеры с итогом удаляются сразу, остальные — только после окончания их окна
  ремонта или ожидания решения;
- активные таймеры и текущие окна ремонта сохраняются.

Для существующей базы добавлена идемпотентная миграция
`supabase/migrations/20261024_003_clear_timer_history.sql`. Её выполнение само
по себе ничего не удаляет: она только создаёт RPC и права на её вызов. Полный
`supabase/schema.sql` содержит ту же функцию для новой установки.

## 4. Тесты и приёмка

1. После отметки `Защищена` в маршруте строка остаётся видимой на доске и имеет
   выбранный итог.
2. Доска выполняет контрольное чтение таймеров после локального события.
3. Кнопка очистки существует только в админ-панели и скрыта до входа.
4. Очистка вызывает `clear_timer_history` с `board_id` и главным админ-ключом.
5. После очистки закрытые строки отсутствуют, активные и ремонтируемые остаются.
6. Полный smoke-набор Playwright проходит.

## 5. Результат

- результат командира сразу отражается на доске и подтверждается данными БД;
- завершённая строка больше не исчезает из-за выключенного фильтра истории;
- физическая очистка Supabase вынесена в заметную, однозначно подписанную кнопку
  главного администратора;
- права на удаление по-прежнему обеспечиваются серверной RPC, а не видимостью
  элемента интерфейса.
