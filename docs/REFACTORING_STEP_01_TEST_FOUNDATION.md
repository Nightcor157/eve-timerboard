# ТЗ этапа 1: тестовый фундамент

Статус: **выполнен 24 октября 2026 года**.

## 1. Цель

Перенести накопленные автоматические проверки внутрь репозитория и сделать их
воспроизводимыми локально и в GitHub Actions до начала изменения архитектуры.

Этап не должен менять пользовательское поведение сайта или схему Supabase.

## 2. Исходное состояние

- В репозитории отсутствуют `package.json`, `tests/` и CI workflow.
- Playwright-скрипты находятся во внешней папке `.codex/visualizations`.
- В тестах есть абсолютные пути к Chrome, зависимостям, репозиторию и снимкам.
- Тесты используют собственный статический сервер и моки Supabase/ESI.
- На момент составления ТЗ существующие проверки проходят.

## 3. Объём работ

### 3.1. Структура

Создать:

```text
package.json
package-lock.json
tests/
  e2e/
  fixtures/
  helpers/
  artifacts/
  static-server.mjs
.github/
  workflows/
    test.yml
```

`tests/artifacts/` не должен хранить постоянные скриншоты каждого запуска.
Артефакты создаются только при необходимости и исключаются через `.gitignore`,
кроме специально утверждённых эталонных изображений.

### 3.2. Команды

В `package.json` предусмотреть минимум:

```text
npm test
npm run test:syntax
npm run test:e2e
npm run test:e2e:stress
```

- `test:syntax` проверяет все JS/MJS-файлы командой `node --check`.
- `test:e2e` запускает основные короткие браузерные сценарии.
- `test:e2e:stress` отдельно запускает наборы на 40 таймерах.
- `npm test` запускает обязательный набор, подходящий для CI.

### 3.3. Перенос сценариев

Перенести и привести к общему стилю проверки:

1. Сортировка доски по тексту и времени.
2. Переключение пользовательского и админского вида.
3. Проверка неправильного админ-ключа.
4. Доступ командира только к назначенным таймерам.
5. Установка и сброс результата командиром.
6. Общий последовательный маршрут и его сохранение между вкладками.
7. Фильтры сторон таймера и типов структур.
8. Сортировка таблиц маршрутов.
9. Скрытие флотов в легенде без удаления строк таблицы.
10. Обратный отсчёт и изменение карты после закрытия цели.
11. Очистка завершённой истории без удаления активных и ремонтируемых таймеров.
12. Стресс-сценарии 40 таймеров / 4 флота.

### 3.4. Устранение зависимости от компьютера

- Все пути строятся через `import.meta.url`, `path.resolve` и корень проекта.
- Playwright запускает свой Chromium; путь к установленному Google Chrome не
  зашивается в тесты.
- Порт сервера выбирается конфигурацией или автоматически.
- Сервер гарантированно останавливается в `finally`, включая упавшие тесты.
- Скриншоты и логи записываются относительно `tests/artifacts/`.
- Тесты не используют реальные админские, пользовательские или флотские ключи.

### 3.5. CI

GitHub Actions должен:

- запускаться для push и pull request в `main`;
- использовать актуальную поддерживаемую LTS-версию Node.js;
- выполнять `npm ci`;
- устанавливать Chromium Playwright с необходимыми зависимостями;
- выполнять `npm test`;
- при ошибке прикладывать логи и снимки как artifact;
- не требовать Supabase secrets, так как RPC мокируются.

## 4. Требования к тестам

- Каждый тест создаёт независимое состояние и не зависит от порядка запуска.
- Даты строятся относительно текущего времени, а не жёстко прошитой даты.
- Моки проверяют имя RPC и значимые параметры запроса.
- Ошибки страницы и необработанные отклонения промисов завершают тест неуспешно.
- Проверки desktop и mobile должны быть явно разделены.
- Стресс-тест должен выводить длительность, число назначений, число уникальных
  целей, число опозданий и нагрузку по флотам.
- На этом этапе число опозданий является метрикой, но не критерием провала:
  критерии оптимальности появятся на этапе 6.

## 5. Критерии приёмки

1. Чистый клон запускает обязательные тесты через `npm ci && npm test`.
2. В тестах нет `C:\\Users`, абсолютных Unix-путей и зависимости от системного
   Chrome.
3. Все двенадцать групп сценариев выше проходят локально.
4. GitHub Actions успешно проходит без секретов Supabase.
5. Падение проверки приводит к ненулевому exit code.
6. После завершения тестов не остаётся процесс статического сервера.
7. Рабочий сайт визуально и функционально не меняется.
8. README содержит команды локального запуска тестов.
9. `docs/PROJECT_MEMORY.md` отмечает этап 1 выполненным, а этап 2 текущим.

## 6. Вне объёма этапа

- изменение RPC и таблиц Supabase;
- исправление конкурентного редактирования;
- изменение алгоритма распределения флотов;
- разделение `app.js` или `routes.js`;
- визуальная переработка интерфейса;
- подключение тестов к рабочей базе пользователя.

## 7. План выполнения

1. Добавить npm-манифест и Playwright.
2. Создать общий сервер, фикстуры и утилиты запуска.
3. Перенести короткие E2E-сценарии.
4. Перенести стресс-сценарии и убрать абсолютные пути.
5. Добавить команды npm и `.gitignore` для артефактов.
6. Добавить GitHub Actions.
7. Прогнать полный набор локально.
8. Обновить README и память проекта.

## 9. Результат выполнения

- Добавлены npm-манифест и зафиксированная версия Playwright `1.62.1`.
- В `tests/` перенесены независимые smoke- и stress-проверки без локальных
  абсолютных путей и настоящих ключей.
- Временный сервер выбирает свободный порт и закрывается в `finally`.
- При падении браузерного теста снимок сохраняется в `tests/artifacts/`.
- GitHub Actions выполняет `npm ci`, устанавливает Chromium и запускает
  обязательный набор для push и pull request в `main`.
- Локально пройдены проверка синтаксиса, 7 smoke-файлов и 8 stress-сценариев.
- Пользовательское поведение приложения и схема Supabase на этапе не менялись.
