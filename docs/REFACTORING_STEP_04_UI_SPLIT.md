# ТЗ этапа 4: разделение интерфейса и карты

Статус: **текущий этап**.

## 1. Цель

Разделить крупные `app.js`, `routes.js` и `styles.css` по областям интерфейса,
не меняя пользовательские сценарии, русские подписи, роли и статическое
развёртывание GitHub Pages.

## 2. Целевая структура

```text
js/
  ui/
    access-view.js
    board-view.js
    timer-editor.js
    fleet-admin-view.js
    route-table-view.js
    route-map-view.js
    system-autocomplete.js
  main.js
css/
  base.css
  board.css
  routes.css
  map.css
  responsive.css
```

`main.js` становится единственной точкой входа страницы. Доменные модули и
сервисы этапа 3 не должны зависеть от DOM.

## 3. Работы

1. Вынести SVG-карту, viewport, zoom/pan и выбор регионов в `route-map-view.js`.
2. Вынести подсказки систем в `system-autocomplete.js`.
3. Вынести отображение маршрутной таблицы и сортировку в `route-table-view.js`.
4. Вынести таблицу доски и редактор таймеров из `app.js` без изменения RPC.
5. Заменить обмен через пользовательские события явным контроллером `main.js`.
6. Разделить CSS по областям в исходном порядке правил, сохранив каскад.
7. Оставить compatibility-модули только там, где это снижает риск шага.

## 4. Ограничения

- не менять визуальный дизайн и HTML-контракт тестовых селекторов;
- не менять SQL и алгоритм распределения флотов;
- не добавлять сборщик или UI-фреймворк;
- не добавлять второй Supabase-клиент;
- не нарушать desktop/mobile и сохранение viewport карты.

## 5. Тесты и приёмка

1. У карты есть отдельные тесты zoom, pan, resize и скрытия флотов.
2. Таблица доски и маршрутная таблица сортируются без знания сетевого слоя.
3. `main.js` — единственный скрипт приложения в `index.html`.
4. Изменение карты не требует правок в управлении профилями флотов.
5. Полный `npm test` проходит, включая 40 таймеров и 4 флота.
6. Визуальные снимки desktop/mobile не имеют наложений или пустой карты.
7. Память проекта отмечает этап 4 выполненным и этап 5 текущим.
