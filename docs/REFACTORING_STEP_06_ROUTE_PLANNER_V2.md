# ТЗ этапа 6: планировщик маршрутов v2

Статус: **текущий этап**.

## 1. Цель

Улучшить распределение целей между флотами после быстрого жадного расчёта и
показывать администратору измеримые характеристики плана. Новый результат
никогда не должен быть хуже текущей эвристики.

## 2. Целевая функция

Планы сравниваются лексикографически, в таком порядке:

1. число назначений с опозданием;
2. суммарное опоздание в миллисекундах;
3. суммарное число прыжков;
4. разброс нагрузки флотов в миллисекундах.

Меньшее значение лучше. Вторичная метрика не может компенсировать ухудшение
более важной.

## 3. Алгоритм

- сохранить `planFleetAssignments` как детерминированный baseline v1;
- построить последовательности целей каждого флота из baseline;
- кэшировать пути между начальными и целевыми системами;
- проверять перенос одной цели в другой флот и обмен целей между флотами;
- после каждого прохода принимать только лучший строго улучшающий вариант;
- ограничить число проходов и кандидатов для предсказуемого времени;
- пересчитать ETA, порядок, пути и метрики принятого плана.

## 4. Интерфейс

После расчёта администратор видит число целей, опозданий, суммарные прыжки,
разброс нагрузки и отметку, удалось ли улучшить baseline.

## 5. Тесты и приёмка

1. Старые golden-тесты v1 остаются неизменными.
2. Есть сценарий, где ранний локальный выбор v1 увеличивает общие прыжки, а v2
   переносит цель без опоздания и улучшает результат.
3. На каждом сценарии `comparePlanMetrics(v2, v1) <= 0`.
4. 8 stress-сценариев по 40 таймеров сохраняют каждую цель ровно один раз.
5. Время расчёта и число проверенных кандидатов входят в возвращаемые метрики.
6. Полный `npm test` проходит, документация и память отмечают roadmap завершённым.
