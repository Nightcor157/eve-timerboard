# ТЗ этапа 5: единая схема и усиление безопасности

Статус: **выполнен 24 октября 2026 года**.

## 1. Цель

Сделать обновление существующей Supabase-базы единым и проверяемым,
закрепить браузерные зависимости и усилить защиту статической страницы без
сброса таймеров, ключей, флотов или назначений.

## 2. Единая схема

- поддерживать только полный `supabase/schema.sql`;
- использовать его и для чистой установки, и для обновления существующей базы;
- создавать таблицы условно, а функции, политики и права приводить к актуальному
  состоянию при каждом запуске;
- PGlite выполняет схему повторно без потери тестовых данных.

## 3. Клиентская безопасность

- закрепить точную стабильную версию `@supabase/supabase-js`;
- добавить совместимую с GitHub Pages Content Security Policy через meta;
- разрешить только собственные файлы, jsDelivr, Supabase и ESI;
- не добавлять секретные ключи, service role или реальные пароли в тесты.

## 4. Ключи и данные

- новые/ротируемые админский и пользовательский ключи должны иметь не менее
  12 символов; существующие хеши продолжают работать;
- ключи флотов остаются случайными 24-символьными значениями;
- добавить `NOT VALID` CHECK для `timers.note` и `timers.distance`, чтобы новые
  неверные значения блокировались без удаления исторических строк;
- документировать безопасную ротацию и порядок восстановления доступа.

## 5. Приёмка

1. Новая база разворачивается одним `supabase/schema.sql`.
2. Существующая база обновляется тем же `supabase/schema.sql` без `DROP TABLE`.
3. Повторный запуск схемы не удаляет данные и не падает.
4. Полный `npm test` проходит с включённой CSP.
5. README явно различает чистую установку и обновление.
6. Память проекта отмечает этап 5 выполненным и этап 6 текущим.

## 6. Выполненный результат

- единый `supabase/schema.sql` содержит все таблицы, RPC, политики и права;
- PGlite выполняет полную схему дважды поверх 40 таймеров;
- новые/ротируемые ключи требуют 12 символов, старые хеши продолжают работать;
- CHECK `NOT VALID` защищают новые значения стороны таймера и итога;
- `EXECUTE` снят с `PUBLIC`, разрешённые RPC явно доступны `anon/authenticated`;
- Supabase JS закреплён на стабильной версии `2.118.0`;
- CSP ограничивает скрипты, соединения, стили, изображения и формы;
- README описывает обновление единым скриптом, ротацию и восстановление доступа.
