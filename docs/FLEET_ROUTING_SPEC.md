# Техническое задание: карта и маршруты флотов

## 1. Цель

Добавить к EVE Timerboard отдельную вкладку для оперативного распределения
активных таймеров между несколькими флотами. Система должна рассчитывать
маршруты автоматически, исключать двойное назначение одной цели и разрешать
командиру флота закрывать только назначенные его флоту таймеры.

## 2. Термины

- **Главный администратор** — пользователь существующего админ-ключа доски.
- **Командир флота** — пользователь отдельного ключа конкретного флота.
- **Зритель** — пользователь ключа просмотра доски.
- **Цель** — активный таймер, включённый в расчёт маршрута.
- **Назначение** — связь между целью и флотом с порядком, ETA и маршрутом.

## 3. Роли и права

| Действие | Зритель | Командир флота | Главный администратор |
|---|:---:|:---:|:---:|
| Смотреть доску и общую карту | Да | Да | Да |
| Смотреть маршрут флота | Нет | Только своего | Всех |
| Отмечать результат цели | Нет | Только своего маршрута | Любой назначенной цели |
| Сбрасывать ошибочный результат | Нет | Только своего маршрута | Да |
| Создавать и редактировать флоты | Нет | Нет | Да |
| Генерировать и отзывать ключи флотов | Нет | Нет | Да |
| Запускать общий перерасчёт | Нет | Нет | Да |

Проверка прав выполняется RPC-функциями Supabase. Скрытие элементов в браузере
не считается защитой.

Обычная доска и админская доска не являются отдельными страницами. Кнопка
`Вид: пользователь / админ` переключает доступные элементы на той же доске.
Вход в админский вид выполняется только после серверной проверки админ-ключа.

## 4. Управление ключами

1. Ключ флота генерируется на сервере после проверки главного админ-ключа.
2. В базе хранится только bcrypt-хеш и последние четыре символа ключа.
3. Полный ключ возвращается один раз при создании или ротации.
4. Старый ключ немедленно перестаёт работать после ротации.
5. Ключ одного флота не даёт доступа к маршрутам и целям другого флота.
6. Ключ флота без действующего ключа просмотра доски не открывает маршрут и
   не позволяет изменить итог цели.

## 5. Профиль флота

Профиль содержит:

- название;
- цвет маршрута;
- текущую стартовую систему;
- среднее время одного прыжка в секундах;
- среднее время работы на одной цели в минутах;
- состояние `активен/выключен`;
- хеш и подсказку ключа.

## 6. Автоматический расчёт

### 6.1. Входные данные

- активные таймеры без результата;
- система и срок каждого таймера;
- активные профили флотов;
- текущая система, скорость и сервисное время флота;
- наборы разрешённых сторон таймера и типов объектов, выбираемые независимо;
- каталог названий, координат и соединений систем из официального EVE SDE;
- публичный ESI как резервный источник маршрута для систем вне локального графа.

### 6.2. Алгоритм первой версии

1. Из активных целей выбираются записи, сторона и тип объекта которых включены
   в соответствующие наборы фильтра. Внутри набора действует `ИЛИ`, между
   наборами — `И`. Затем цели сортируются по ближайшему сроку.
2. Для каждой цели локальный граф SDE рассчитывает путь от текущей конечной
   точки каждого флота.
3. Рассчитываются ETA, опоздание и последующая занятость флота.
4. Цель получает флот с минимальным опозданием, затем с минимальным ETA.
5. После назначения флот считается занятым до максимума из ETA и времени
   таймера плюс его сервисное время.
6. Одна цель может принадлежать только одному флоту.
7. Результат целиком заменяет предыдущий сохранённый план одной транзакцией.
8. Перед расчётом интерфейс проверяет и автоматически сохраняет изменённые
   параметры всех профилей флотов. Отдельно нажимать `Сохранить` не требуется.
9. Число целей между флотами намеренно не выравнивается: выбор определяется
   прогнозируемым ETA после ранее назначенных целей, поэтому более быстрый или
   ближе расположенный флот может получить больше целей.

Алгоритм является детерминированной эвристикой для оперативной работы. Он не
обещает математически оптимальное решение задачи VRPTW, но приоритетно
сохраняет достижимость ближайших дедлайнов и явно показывает опоздания.

### 6.3. Граф маршрутов и ESI

Основной расчёт кратчайшего пути выполняется в браузере по связям звёздных врат
из локального официального SDE. Это исключает до `число целей × число флотов`
сетевых запросов при массовом расчёте. Если система отсутствует в локальном
графе или путь в нём не найден, используется официальный публичный ESI-маршрут
с предпочтением `Shorter`. Результаты кэшируются на время работы страницы.
Неизвестные системы и сетевые ошибки должны показываться пользователю и не
приводить к частичному сохранению плана.

### 6.4. Каталог систем и карта

Компактный файл `data/solar-systems.json` генерируется из официального
[EVE Static Data Export](https://developers.eveonline.com/docs/services/static-data/).
Он содержит системы известного космоса, координаты
`position2D`, security status и соседей по звёздным вратам. Каталог используется
для автодополнения, расчёта путей и отрисовки карты без тысяч запросов к ESI.

Карта проецирует официальные
[2D-координаты EVE](https://developers.eveonline.com/docs/guides/map-data/),
показывает системы и ворота задействованных регионов приглушённым фоном,
а рассчитанный маршрут рисует поверх цветной линией. Для больших межрегиональных
операций действует лимит фоновых систем с приоритетом регионов старта и целей.
Старт и системы с таймерами имеют отдельные маркеры. Подробные подписи
появляются только у систем рассчитанного маршрута, а их экранный размер
адаптируется к масштабу. Колесо мыши масштабирует карту относительно курсора,
зажатая левая кнопка перемещает карту. Нижняя ручка изменяет высоту карты.
Положение и масштаб сохраняются раздельно для общей карты и маршрутов флотов,
высота сохраняется для всей карты в браузере.

## 7. Интерфейс

### Общая карта

- поле стартовой системы пользователя с автодополнением и проверкой названия;
- активные цели;
- мультивыбор сторон таймера и типов объектов перед расчётом;
- последовательный маршрут по целям с тем же алгоритмом, что и для одного флота;
- рекомендуемая следующая цель;
- путь, число прыжков, ETA и запас времени;
- визуальное выделение срочных и недостижимых целей.

### Маршруты флотов

- выбор флота из выпадающего меню;
- ввод и необязательное локальное запоминание ключа;
- карта маршрута выбранного флота;
- масштабирование колесом и кнопками, перетаскивание ЛКМ и возврат к виду всей карты;
- увеличение до `16×` для подробного просмотра целей внутри одного региона;
- переключатели видимости флотов в цветной легенде без скрытия строк таблицы;
- упорядоченный список целей;
- ETA, число прыжков и запас времени;
- кнопки `Защищена`, `Уничтожена` и `Сброс` для командира в строке назначенной цели;
- отображение уже поставленного итога цели.

После успешного входа по ключу флота кнопки `Защищена`, `Уничтожена` и `Сброс`
показываются в строке маршрута и в столбце `Итог` обычной доски только у целей,
назначенных этому флоту. Остальные столбцы не переходят в режим редактирования.

### Панель главного администратора

- создание профиля;
- редактирование параметров;
- включение и выключение;
- выпуск нового ключа;
- удаление профиля;
- выпадающие фильтры с независимыми переключателями сторон таймера и типов объектов;
- автоматическое сохранение изменённых профилей и перерасчёт всех маршрутов;
- просмотр всех маршрутов без ключей флотов.

## 8. Данные Supabase

- `fleet_profiles` — профили и хеши ключей;
- `fleet_assignments` — сохранённый план;
- `timer_result_events` — журнал изменения результатов.

Прямой доступ `anon` и `authenticated` к таблицам запрещён. Чтение и запись
выполняются только через `security definer` RPC с фиксированным `search_path`.

## 9. Ограничения первой версии

- рассчитываются маршруты по обычной сети звёздных врат из SDE, с резервным
  обращением к ESI;
- Ansiblex и временные червоточины пока не добавляются в маршрут;
- положение флота вводится вручную главным администратором с выбором системы
  из локального каталога;
- маршрут пересчитывается главным администратором после изменения целей или
  положения флота;
- карта использует официальные координаты и связи EVE, но показывает коридор
  текущего маршрута и его соседей, а не весь интерактивный клон DOTLAN;
- пользовательские Ansiblex отсутствуют в официальном графе SDE и пока не
  участвуют в расчёте.

## 10. Критерии приёмки

1. Главный администратор создаёт минимум два флота и получает разные ключи.
2. Повторное чтение базы не раскрывает полный ключ.
3. Система распределяет каждый активный таймер не более чем одному флоту.
4. Командир видит только маршрут выбранного флота.
5. Ключ другого флота не открывает маршрут и не меняет результат.
6. Командир меняет результат только назначенной ему цели.
7. Главный администратор видит все маршруты и сохраняет прежние права.
8. Существующие таймеры и ключ просмотра не сбрасываются при обновлении SQL.
9. При ошибке расчёта или резервного запроса ESI старый сохранённый план остаётся целым.
10. Интерфейс работает на настольном и мобильном экране без наложений.
11. При вводе системы появляются подходящие варианты, а опечатка блокирует
    сохранение или расчёт с понятным сообщением.
12. Изменение текущей системы флота и нажатие `Сохранить и рассчитать`
    использует новое значение в этом же расчёте.
13. Пользователь без проверенного админ-ключа при выборе админского вида видит
    окно ввода ключа и не получает элементов редактирования.
14. Командир флота получает кнопки результата в маршруте и на обычной доске только у целей
своего маршрута; зритель не получает эти кнопки.
15. До проверки ключа просмотра вкладка маршрутов не открывается, а RPC
    маршрута отклоняет запрос без действующего ключа просмотра.
16. В общей таблице маршрута и маршруте флота название системы копируется
    кликом или клавишей `Enter`/`Пробел` с визуальным подтверждением.
17. После установки итога карта скрывает только входящий отрезок закрытой цели,
    сохраняет путь от неё к следующей цели и не соединяет разрывы ложной линией.
18. Администратор может одновременно включить несколько типов объектов и сторон
    таймера; расчёт назначает только цели, попавшие в оба набора фильтра.
19. Отключение флота в легенде сразу убирает с карты только его маршрут и не
    удаляет назначения или строки общей таблицы.
20. Общая карта позволяет одновременно выбрать несколько сторон таймера и типов
    объектов с той же логикой фильтрации, что и расчёт маршрутов флотов.
